1.2 Deploy IaaS and PaaS on Azure

2 lab exercises
Part A – Deploy IaaS using Azure Virtual Machine IaaS

Step 1: Open Azure Portal

  1. Open a web browser.
  2. Go to the Azure Portal (portal.azure.com).
  3. Sign in using your Azure account.

Step 2: Create a Virtual Machine

  1. Search for Virtual machines.
  2. Click Create→Azure virtual machine.
  3. Select or create a Resource group.
  4. Enter a VM name.
  5. Select an appropriate Region.
  6. Select an operating system such as Ubuntu Linux.
  7. Select a suitable VM size.
  8. Configure authentication.
  9. Configure the required networking options.
  10. Click Review + create.
  11. Click Create.

Step 3: Interact with the IaaS VM

After deployment:

  1. Open the VM.
  2. Check its CPU, memory, disk, networking, and operating system settings.
  3. Use the Connect option to connect to the VM.
  4. Open the Linux terminal.
  5. Execute basic commands such as:
Bash 
uname -a              # kernel and OS details
cat /etc/os-release   # Linux distribution
lscpu                 # CPU information
free -h               # memory usage
df -h                 # disk usage
ip addr               # network interfaces
Observation: In IaaS, the user has greater control over the virtual machine, operating system, storage, and network configuration.
Part B – Deploy PaaS using Azure App Service PaaS

Step 1: Open Azure App Service

  1. In the Azure Portal, search for App Services.
  2. Click Create→Web App.

Step 2: Configure Web App

  1. Enter the required details. Example:
    Resource Group
    Cloud-PaaS-RG
    App Name
    cloud-paas-demo
    Runtime Stack
    Python
    Operating System
    Linux
  2. Select an appropriate Region.
  3. Select a suitable Pricing plan.
  4. Click Review + create.
  5. Click Create.

Step 3: Deploy an Application

Create a simple web application using Python Flask. Example:

Python · app.py 
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Welcome to PaaS Cloud Computing"

if __name__ == "__main__":
    app.run()

Deploy the application to Azure App Service.

Step 4: Interact with the Application

  1. Open the deployed App Service.
  2. Click the application URL.
  3. Verify that the web application is running.
In PaaS, the user does not need to manage the underlying physical server or operating system.
Observation: PaaS provides less infrastructure control than IaaS but makes application deployment easier because the cloud provider manages the underlying platform.

2.1 Static Website on Azure Storage

1 lab exercise
To create a free Azure account and deploy a simple static website using Azure Storage. Storage

Step 1: Create an Azure Account

  1. Open a web browser.
  2. Go to the Microsoft Azure website (azure.microsoft.com).
  3. Click Start free.
  4. Sign in using a Microsoft account.
  5. Complete the required registration and verification process.
  6. After successful registration, open the Azure Portal.

Step 2: Create a Resource Group

  1. In the Azure Portal, search for Resource groups.
  2. Click Create.
  3. Select the Azure Subscription.
  4. Enter the Resource Group name as RG-StaticWebsite.
  5. Select a suitable Region.
  6. Click Review + create.
  7. Click Create.

Step 3: Create a Storage Account

  1. In the Azure Portal, search for Storage accounts.
  2. Click Create.
  3. Select the previously created Resource Group RG-StaticWebsite.
  4. Enter a unique name for the Storage Account.

    Use 3–24 lowercase letters and numbers only, e.g. staticsite12345.

  5. Select a suitable Region.
  6. Select Standard performance.
  7. Click Review + create.
  8. Click Create.
  9. After deployment is complete, click Go to resource.

Step 4: Enable Static Website

  1. Open the created Storage Account.
  2. From the left-side menu, select Static website.
  3. Change the Static website option from Disabled to Enabled.
  4. Enter index.html as the Index document name.
  5. Enter 404.html as the Error document path.
  6. Click Save.

Step 5: Create the Website Files

  1. Open a text editor such as Notepad.
  2. Create a file named index.html and add the following HTML code:
HTML · index.html 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My Azure Static Website</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <main class="card">
    <h1>Hi there!</h1>
    <p>This static website is hosted on Azure Storage.</p>
    <button onclick="alert('Hello from Azure!')">Click me</button>
  </main>
</body>
</html>
  1. Create a file named style.css and add the following CSS code:
CSS · style.css 
body {
  margin: 0;
  min-height: 100vh;
  display: flex;
  align-items: center;
  justify-content: center;
  font-family: "Segoe UI", Arial, sans-serif;
  background: #f3f6fb;
}

.card {
  background: #fff;
  padding: 32px 40px;
  border-radius: 8px;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.12);
  text-align: center;
}

h1 {
  margin-top: 0;
  color: #0078d4;
}

button {
  padding: 8px 20px;
  border: none;
  border-radius: 4px;
  background: #0078d4;
  color: #fff;
  cursor: pointer;
}
In Notepad, choose Save as type: All files (*.*) when saving, so the files are not saved as index.html.txt or style.css.txt. Save both files in the same folder.

Step 6: Open the $web Container

  1. Go back to the Azure Storage Account.
  2. Select Containers from the left-side menu.
  3. Open the automatically created $web container.
  4. This container is used to store the static website files.

Step 7: Upload Website Files

  1. Inside the $web container, click Upload.
  2. Click Browse for files.
  3. Select index.html.
  4. Select style.css.
  5. Click Upload.
  6. Wait until the files are successfully uploaded.

Step 8: Access the Static Website

  1. Go to Static website in the Storage Account.
  2. Find the Primary endpoint.
  3. Copy the website URL provided by Azure.
  4. Open a new browser tab.
  5. Paste the copied URL.
  6. Press Enter.
  7. Verify that the static website is displayed successfully.

Step 9: Test the Website

  1. Check whether the webpage is displayed correctly.
  2. Verify that the HTML content is visible.
  3. Check whether the CSS styling is applied.
  4. Click the button on the webpage, if included.
  5. Verify that the website is accessible through the Azure URL.

  2. Open RG-AzureLab.
  3. Verify that the following resources are available:
    • Virtual Machine

Result: Thus, the Azure Portal was successfully explored, and a Resource Group, Virtual Machine, and Storage Account were created and managed successfully.

2.3 Blob Storage and Data Persistence

1 lab exercise
To create a Blob container in Azure Storage and upload and download files to verify data persistence. Blob

Step 1: Open Azure Portal

  1. Open a web browser.
  2. Go to the Azure Portal (portal.azure.com).
  3. Sign in using your Microsoft account.
  4. The Azure Portal Dashboard will be displayed.

Step 2: Open Storage Account

  1. In the Azure Portal, search for Storage accounts.
  2. Click Storage accounts.
  3. Select the previously created Storage Account.
  4. The Storage Account Overview page will be displayed.

Step 3: Create a Blob Container

  1. From the left-side menu, select Data storage.
  2. Click Containers.
  3. Click + Container.
  4. Enter the container name as labcontainer.
  5. Click Create.
  6. The labcontainer will be created successfully.

Step 4: Create a File

  1. Open Notepad on the computer.
  2. Type some sample text, for example:
Text · sample.txt 
Azure Blob Storage Lab
This file is stored in the cloud.
  1. Save the file as sample.txt.

Step 5: Upload the File

  1. Open the labcontainer.
  2. Click Upload.
  3. Click Browse for files.
  4. Select the sample.txt file.
  5. Click Upload.
  6. The file will appear inside the container.

Step 6: View the Uploaded File

  1. Select sample.txt.
  2. Observe the file details.
  3. Check the file name and size.
  4. The file is now stored in Azure Blob Storage.

Step 7: Download the File

  1. Select the uploaded sample.txt file.
  2. Click Download.
  3. The file will be downloaded to the local computer.
  4. Open the downloaded file.
  5. Verify that the original content is present:
Expected content
Azure Blob Storage Lab
This file is stored in the cloud.

Step 8: Edit the File in Azure

  1. Open the labcontainer container.
  2. Click the uploaded sample.txt file.
  3. Click Edit.
  4. The file content will be displayed in the editor.
  5. Add the following content:
Text · sample.txt 
Azure Blob Storage Lab
This file is stored in the cloud.
File edited successfully in Azure.
  1. Click Save.
  2. The changes will be saved directly to Blob Storage.

Step 9: Download the Modified File

  1. Select the edited sample.txt file.
  2. Click Download.
  3. Save the file to the local computer.
  4. Open the downloaded file.
  5. Verify that the newly added content is present.

Step 10: Verify Data Persistence

  1. Close the Azure Portal.
  2. Open the Azure Portal again.
  3. Navigate to the Storage Account.
  4. Open Containers→labcontainer.
  5. Select sample.txt.
  6. Click Edit.
  7. Verify that the added content is still present.
  8. Download the file again and verify its contents.
Result: Thus, a Blob container was successfully created in Azure Storage, and a file was uploaded and downloaded successfully. The persistence of the uploaded data was verified.

Follow these steps to deploy your Python Flask Web App to Azure App Service seamlessly without tweaking Portal settings manually.

Zip only the direct contents inside your directory (not the enclosing folder itself):

4 Run Deployment Commands

Run the following Azure CLI commands sequentially in your terminal:

PowerShell / Terminal 
# 1. Log in to Azure
az login

# 2. Create Linux App Service Plan
az appservice plan create --name myAppServicePlan --resource-group TestResource --sku B1 --is-linux

# 3. Create Web App and configure startup command automatically
az webapp create --name TestWebAppprogram --resource-group TestResource --plan myAppServicePlan --runtime "PYTHON:3.11" --startup-file "gunicorn --bind=0.0.0.0:8000 app:app"

# 4. Enable remote build to install requirements.txt automatically
az webapp config appsettings set --name TestWebAppprogram --resource-group TestResource --settings SCM_DO_BUILD_DURING_DEPLOYMENT=true

# 5. Deploy the application zip package
az webapp deploy --name TestWebAppprogram --resource-group TestResource --src-path app.zip --type zip
💡 Why this works automatically: Passing --startup-file "gunicorn --bind=0.0.0.0:8000 app:app" during creation configures Azure to launch app.py directly, skipping manual portal configurations!
